Wins #1–2

Infrastructure monitoring + APM across the estate

Infrastructure

Every layer, every cloud

Host agents on bare metal/VMs. Cluster Agent + DaemonSet on K8s. Native cloud integrations for AWS/GCP/Azure. NDM via SNMP for routers/switches. DBM across Oracle, PostgreSQL, MySQL, Redis — query-level performance, explain plans, lock analysis.

Why it mattered

Post-merger, IOH had zero correlated telemetry. Different teams used different tools for different infra. A single unified view was the foundation everything else built on.

APM Enterprise

End-to-end distributed tracing

Single trace ID follows a request: Nginx → Tomcat → DB → external API. Service Map auto-discovered. Continuous Profiler — code-level CPU/memory hotspots. Error Tracking auto-groups exceptions. Tracers for Java, Python, Go, .NET, Node.js.

The correlation

Click a slow API response → see the database lock → see the container resource constraint → see the network blip. Every signal connected by trace ID. That's not a feature — that's the architecture decision.

Wins #3–4

User experience + log intelligence

RUM + Session Replay

See what users see

Browser SDK captures Core Web Vitals (LCP, FCP, CLS, INP). Full session replay with privacy controls. Click a replay → see the backend trace. At 95M subscribers, real user data, not assumptions.

Synthetics

Catch it first

API tests + browser journeys from global locations. SSL cert expiry, DNS resolution, multi-step user flows. Proactive: catches outages before users report them. Linked to APM for root cause.

Log Management

Correlated pipeline

Multi-source: DD Agent, Fluentd, CloudWatch, Pub/Sub, Event Hub. Grok parsers, exclusion filters. Every log carries dd.trace_id. Click log → trace. Click trace → logs. 7-day online + archive.

RUM tells you what users experience. Synthetics tells you what's broken before they complain. Logs tell you why. APM connects them all. One trace ID across every signal.

Win #6 · The Architecture Call

"Should we build a custom RCA agent?"

Proposed: general-purpose LLM → Datadog MCP tool calls → query metrics/logs/traces → root cause in 45 seconds.

Not trained for RCA

Can't distinguish cause from symptom.

No eval framework

Confident + wrong = wrong path.

RAG ≠ reasoning

Retrieving past incidents ≠ understanding this one.

45s unbenchmarked

Assumption, not tested spec.

My Call

Don't build the agent.
Build the system around one.

Use Bits AI SRE — purpose-built, trained on 1T+ observability datapoints. Redirect team effort to what genuinely needed building:

→ Event routing + ticket creation
→ ServiceNow bidirectional sync
→ Human-in-the-loop governance
→ Feedback loop for accuracy

The senior move on AI: own the integration and governance around a validated model.

Win #8 · ITSM

ServiceNow — bidirectional, not just a webhook

DATADOG → SERVICENOW

Monitor triggers → webhook → auto-creates incident. Severity mapped to priority. Service mapped to CMDB CI. Custom fields: u_datadog_monitor_id, u_datadog_url. Deduplication — same alert updates existing ticket.

SERVICENOW → DATADOG

Ticket resolved → Business Rule → resolves Datadog alert. Work notes sync back. No orphaned tickets. No orphaned alerts.

SECURITY TICKETS TOO

SAST/SCA findings auto-create issues. Fix → re-scan → auto-close. Same integration for ops and security. 50% less integration surface.

SLA Enforcement

Sev 115m response · 1h restore · 1d resolve
Sev 230m response · 4h restore · 3d resolve
Sev 32h response · 8h restore · 5d resolve

Key decision: one ITSM integration for both observability incidents and security findings. Two ticket queues, same bidirectional plumbing. Reduced integration surface by 50%.

Win #9 · Automation + Adoption

Playbooks that outlast the people who wrote them

Auto-Remediation

Pre-approved playbooks

Known failure modes: restart service, scale pod, clear cache, rotate creds. Approved upfront, executed at alert time. Every action audited + reversible.

Intelligent Alerting

ML-powered monitors

Anomaly detection — baseline deviation. Forecast monitors — predict exhaustion. Composite alerts — multiple conditions before page. No alert fatigue.

CI/CD Visibility

Deploy events on metrics

Pipeline monitoring across GitLab CI / Jenkins. Deploy events overlaid on dashboards. Argo CD / Flux tracking. "Did the last deploy cause this?"

Why this mattered for IOH: Operations are managed-services-led — partner teams, subcontractors, follow-the-sun. Workflows encode institutional knowledge as executable playbooks. The platform remembers what to do, even when the on-call person has never seen this failure.

3-year adoption ramp: Phase 1 — core infra + APM. Phase 2 — security + RUM. Phase 3 — AIOps + full autonomy. Each phase has adoption gates — not just deployment, but actual usage by ops teams.

Engineering Honesty

The hard calls under real constraints

Constraint

COTS you can't instrument

Siebel, Tibco — closed binaries. OTel where exposed, agents where possible, metrics-only where neither works. Triage by instrumentability upfront. Scope honestly.

Constraint

Telco-scale overhead

At 95M subscribers, even 2% CPU overhead matters. Mandatory perf testing. Discipline on debug logs + profilers in production PoVs. Every agent config reviewed.

Constraint

Partner dynamics

MII is the SI. IOH managed services runs ops. I could have disintermediated — but keeping trusted partners inside the deal was the right call. They amplify, not compete.

The thread through every decision: at this scale, architecture choices compound. One trace ID across every signal. One integration for ops + security. One platform for all clouds. Every decision reduced surface area — and that's what made it winnable.

Reflections

What worked, what I'd change, what it taught me

Went Well

The RCA build-vs-buy reframe. Framing for the CIO as reactive → proactive. Keeping partners inside the deal. Embedding security in the same platform as observability — one integration surface.

Do Differently

Align with IS function earlier. Triage COTS instrumentability before the PoV. Get ahead of SAST accuracy concerns proactively. Start adoption measurement in Phase 1.

Learned

In a managed-services enterprise, adoption is the product. The senior AI move: own integration + governance around a validated model. At telco scale, architecture decisions compound more than any feature.
