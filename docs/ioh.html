Win #1 · Infrastructure

Unified visibility across the hybrid estate

On-Premise

Bare Metal & VMs

DD Agent on every host. CPU, memory, disk, process-level visibility. Live Containers for real-time process inspection. Nginx, Tomcat, Siebel, Tibco — all instrumented.

Kubernetes

Cluster Agent + DaemonSet

Cluster Agent acts as proxy — reduces API server load by centralising metadata. DaemonSet per node. NPM for pod-to-pod traffic. Auto-discovery for container workloads.

Multi-Cloud

AWS · GCP · Azure

Native cloud integrations. EC2, EKS, Lambda (AWS). GCE, GKE, Cloud Run (GCP). AKS, VM Scale Sets (Azure). CloudWatch, Stackdriver, Azure Monitor — all funnelled into one platform.

Network

NDM + NPM

SNMP polling for routers/switches. DNS monitoring. Network heatmaps for traffic flow analysis. First time IOH had network device telemetry correlated with application metrics.

Database

DBM across 4 engines

Oracle, PostgreSQL, MySQL, Redis. Query-level performance, explain plans, lock analysis. One agent per DB instance — Cluster Agent ensures no duplicates. Managed DB support across all 3 clouds.

Win #2 · APM Enterprise

End-to-end traces across every service

  • Distributed tracing across on-prem and cloud services — single trace ID follows a request through Nginx → Tomcat → DB → external API.
  • Service Map auto-discovered — dependencies, error rates, latency percentiles (p50/p95/p99) visualised in real time.
  • Continuous Profiler — code-level CPU and memory hotspots in production. Zero-config overhead.
  • Error Tracking — auto-groups exceptions across services. Links traces to logs to infra metrics.
  • APM tracers for Java, Python, Go, .NET, Node.js, PHP, Ruby — covering IOH's polyglot stack.
Why This Mattered

The correlation gap was the real problem

IOH had APM before — but it couldn't correlate a slow API response to a database lock to a container resource constraint to a network blip. Every signal was isolated.

With unified APM + Infra + Logs + NPM, a single click goes from symptom → root cause across the full stack. That's not a feature — it's the architecture decision that made everything else possible.

Win #3 · User Experience

Real users + synthetic probes = full picture

RUM

Real User Monitoring

Browser SDK captures Core Web Vitals (LCP, FCP, CLS, FID, INP) from real users. Error tracking, resource waterfall, performance by geography/device/browser.

Session Replay

See what the user saw

Full session replay with privacy controls. Reproduces user-reported bugs visually. Linked to traces — click a replay event, see the backend trace.

Synthetics

API & browser tests

Proactive monitoring from global locations. API endpoint health, multi-step browser journeys, SSL certificate expiry, DNS resolution. Catches outages before users do.

The Connection

RUM tells you what users experience (real traffic, real pain). Synthetics tell you what's broken before anyone complains (proactive). APM tells you why (backend root cause). All three linked by trace ID. For a 95M-subscriber telco, this was the difference between "we think there's an issue" and "we know, we're already fixing it."

Pipeline Integration

GitLab ↔ Datadog ↔ ServiceNow

Datadog scans the code in GitLab CI. Policy violations block the build. Vulnerabilities auto-create ServiceNow tickets. Developer pushes fix → ticket auto-closes. Full traceability from commit to production to ticket.

Why This Decision

Embedded > bolted-on

IOH evaluated standalone SAST tools. The decision: embed security into the same platform that owns observability. One agent, one trace ID, one platform. A SAST finding correlates to an APM trace correlates to a RUM error. That closed the loop between "we found a vuln" and "here's the user impact."

Win #4 · Security Stack Detail

Four layers of application security

SAST

Static Analysis

Scans source code for vulnerabilities before build. Custom rulesets tuned for IOH. IDE integration pushes findings to developers in real time.

Shift-left · pre-commit

SCA

Software Composition

Scans open-source dependencies. CVE matching, license compliance, transitive dependency analysis. Enforcement gate blocks deploy on critical CVEs.

Supply chain · build-time

IAST

Interactive Testing

Instruments running application in staging/UAT. Detects vulns during functional testing — real request flows, real data paths. Correlated to APM traces.

Runtime · test phase

RASP

Runtime Protection

Blocks attacks in production — SQLi, XSS, SSRF, path traversal. Works inside the application runtime. Telemetry correlates RASP blocks to SAST/SCA findings.

Production · real-time

⛔

Enforcement Gate: Critical SAST/SCA finding → pipeline stops → ServiceNow ticket auto-created → dev pushes fix → pipeline re-runs → if clean, deploy proceeds. No human can override a critical finding.

Win #5 · Log Management

Unified log pipeline with intelligent retention

Ingestion

Multi-source collection

DD Agent collects from hosts. Fluentd/Logstash aggregators for legacy systems. Cloud-native forwarding: CloudWatch → DD, Pub/Sub → DD, Event Hub → DD. One pipeline, all sources.

Processing

Log pipelines

Parse, enrich, filter at ingestion. Grok parsers for custom formats. Attribute remapping for consistent schema. Exclusion filters reduce noise without losing searchability.

Correlation

Logs ↔ Traces ↔ Metrics

Every log line carries dd.trace_id and dd.span_id. Click a log → see the trace. Click a trace → see every log line from that request. This is the correlation IOH never had.

Retention

7-day live + archive

Log Events with 7-day online retention for investigation. Rehydration from S3/GCS for compliance. Cost-optimised: index what matters, archive the rest.

Win #6 · The Architecture Decision

"Should we build a custom RCA agent?"

Proposed Design

Take a general-purpose LLM → give it Datadog access via MCP tool calls → query metrics, logs, traces → reason to a root cause in 45 seconds.

The intent was right. The implementation had real gaps.

Not trained for RCA

General model can't distinguish root cause from correlated symptom.

No eval framework

No accuracy target, no wrong-answer detection. Confident wrong = engineers down the wrong path.

RAG ≠ reasoning

Retrieving a similar past incident ≠ understanding this incident.

Unbenchmarked claims

45s was an assumption, not a tested spec.

My Call

Don't build the agent. Build the system around one.

Use Bits AI SRE (purpose-built, trained on 1T+ observability datapoints, ~$750K compute) for diagnosis. Redirect team effort to what genuinely needed building:

  • Pipeline: event routing, ticket creation, finding write-back
  • Integration: ServiceNow ↔ Datadog bidirectional sync
  • Governance: human-in-the-loop approval for remediation
  • Feedback loop: outcomes improve accuracy over time

The senior move on AI was not building the model — it was owning the integration and governance around a validated one.

Win #8 · ITSM Integration

ServiceNow — bidirectional, not just a webhook

Datadog → ServiceNow

Alert → Incident

  • Monitor triggers → webhook payload to ServiceNow
  • Field mapping: severity → priority, service → CMDB CI
  • Custom fields: u_datadog_monitor_id, u_datadog_url
  • Deduplication — same alert updates existing ticket, not new one
ServiceNow → Datadog

Resolve → Close

  • Ticket resolved → Business Rule fires → resolves Datadog alert
  • Work notes sync back to Datadog event stream
  • No orphaned tickets, no orphaned alerts
Security Tickets

Vulns → ServiceNow too

SAST/SCA findings auto-create ServiceNow issues. Dev pushes fix → re-scan passes → ticket auto-resolved. Same workflow for security and ops.

This was a key decision: one ITSM integration for both observability incidents and security findings. Two separate ticket queues, same bidirectional plumbing. Reduced integration surface by 50%.

Win #9 · Automation

Workflow automation — from alert to remediation

Auto-Remediation

Pre-approved actions

Defined playbooks for known failure modes: restart service, scale pod, clear cache, rotate credentials. Human-approved upfront, machine-executed at alert time.

Governance: every auto-action is audited and reversible.

Alerting

Intelligent monitors

Anomaly detection — ML-based baseline deviation. Forecast monitors — predict exhaustion before it happens. Composite alerts — multiple conditions before page.

CI/CD Visibility

Pipeline monitoring

Jenkins / GitLab CI pipeline visibility. Deploy events overlaid on metrics. Argo CD / Flux GitOps deployment tracking. Rollback correlation — "did the last deploy cause this?"

Why Workflow Automation Was Critical

IOH's operations are managed-services-led — partner teams, subcontractors, follow-the-sun rotations. You can't rely on a single SRE knowing the system. Workflows encode institutional knowledge as executable playbooks. The platform remembers what to do, even when the person on call has never seen this failure before.

Win #10 · Deployment Architecture

Three agent models, one secure transport layer

VM / Bare Metal

Host Agent

DD Agent v7+ installed per host. Collects metrics, traces, logs. APM tracer library injected into application runtime. Configuration managed remotely from Datadog UI.

HTTPS bidirectional · remote config

Kubernetes

Cluster Agent + DaemonSet

Cluster Agent: centralises metadata, reduces API server load, distributes monitoring tasks. DaemonSet: one node agent per K8s node. Auto-discovery for new pods. NPM for network flow.

One agent per DB instance · no duplicates

Secure Transport

Multiple egress paths

HTTPS 443 (default). AWS PrivateLink for AWS workloads. Azure Private Endpoint. GCP Private Service Connect. Optional: Private Agent Gateway (TCP 10516) for air-gapped segments.

All telemetry encrypted in transit

RBAC & Governance

SSO integration with IOH identity provider. Role-based access control — SRE sees everything, dev team sees their services, management sees dashboards. Audit logs track every configuration change. Compliance requirement for a regulated telco.

Engineering Honesty

The honest calls under real constraints

Instrumentation

COTS you don't own

OTel where exposed; binaries you can't touch (Siebel); agents hidden in app UIs (Tibco). Triage by instrumentability upfront. Scope honestly — not everything can be traced.

Performance

Telco overhead

Agents & tracers add CPU + latency. At 95M subscribers, even 2% overhead matters. Mandatory perf testing. Discipline on debug logs & profilers in prod PoVs.

Governance

Security-gated SLA

Critical vuln with no fix auto-blocks deploy. Sev1: 15m response · 1h restore. Slower delivery, enforced safety. This was non-negotiable.

Adoption

3-year ramp

You can't instrument a $6B merged telco in a quarter. Phase 1: core infra + APM. Phase 2: security + RUM. Phase 3: AIOps + full autonomy. Each phase has adoption gates — not just deployment, but actual usage by the ops teams.

Partner Model

Build through, not around

MII is the SI. IOH managed services runs operations. I could have tried to disintermediate — but keeping trusted partners inside the deal was the right call. They amplify, not compete.

Reflections

What I'd keep, change, and what it taught me

Went Well

The RCA build-vs-buy reframe. Framing incident management for the CIO as reactive → proactive in business terms. Keeping IOH's trusted partners inside the deal. Embedding security into the same platform as observability — one integration surface, not two.

Do Differently

Align with the customer's IS function earlier. Triage COTS instrumentability before the PoV — not during. Get ahead of SAST accuracy concerns proactively. Start the adoption measurement framework in Phase 1, not Phase 2.

Learned

In a managed-services-led enterprise, adoption is the product. The senior move on AI was not building the model — it was owning the integration and governance around a validated one. And at telco scale, the architecture decision matters more than any individual feature.
