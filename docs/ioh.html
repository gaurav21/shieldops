Observability Stack

Infrastructure + APM + Database + Logs

Infra + K8s

Every layer, every cloud

Host agents on VMs. Cluster Agent + DaemonSet on K8s — centralises metadata, reduces API Server load. Native integrations for AWS/GCP/Azure. NDM via SNMP for routers/switches. First time IOH had network + app telemetry correlated.

Database Monitoring

4 engines, query-level depth

Oracle, PostgreSQL, MySQL, Redis + managed cloud DBs. Query performance, explain plans, lock analysis. One agent per instance — Cluster Agent ensures no duplicates.

APM Enterprise

End-to-end distributed tracing

Single trace ID: Nginx → Tomcat → DB → external API. Service Map auto-discovered. Continuous Profiler — code-level hotspots. Error Tracking — auto-groups exceptions. Tracers for Java, Python, Go, .NET, Node.js.

Click a slow API → see the DB lock → see the container constraint → see the network blip. Every signal connected by trace ID. That's the architecture decision.

Log Management

Correlated pipeline

Multi-source: Agent, Fluentd, CloudWatch, Pub/Sub, Event Hub. Grok parsers. Every log carries dd.trace_id. Click log → trace → infra. 7-day online + archive.

Hindsight Should have triaged COTS instrumentability (Siebel, Tibco — closed binaries) before the PoV, not during. Some things just can't be traced — scope that honestly upfront.

User Experience

Real users + synthetic probes at 95M-subscriber scale

RUM

Real User Monitoring

Browser SDK captures Core Web Vitals — LCP, FCP, CLS, INP. Error tracking, resource waterfall, performance by geography/device/browser. Real data from real users, not assumptions.

Session Replay

See what the user saw

Full session replay with privacy controls. Reproduce user-reported bugs visually. Click a replay event → see the backend trace. Visual proof meets technical depth.

Synthetics

Catch it before they do

API tests + browser journeys from global locations. SSL cert expiry, DNS resolution, multi-step flows. Proactive: detects outages before users report them.

RUM = what users experience. Synthetics = what's broken before they complain. APM = why. Logs = the detail. One trace ID across every signal.

Hindsight Should have pushed for mobile SDK earlier — 95M subscribers are overwhelmingly mobile-first. We led with browser RUM, but the real user pain was in the app experience.

The Architecture Call

"Build a custom RCA agent?" — No. Build the system around one.

Proposed: General LLM → MCP tool calls → query metrics/logs/traces → root cause in 45s.

Not trained for RCA

Can't distinguish cause from symptom.

No eval framework

Confident + wrong = wrong path.

RAG ≠ reasoning

Similar incident ≠ understanding this one.

45s unbenchmarked

Assumption, not tested spec.

My call: Use Bits AI SRE (1T+ datapoints, purpose-built). Redirect effort to integration, governance, feedback loop.

Trade-off: gave up "we built our own agent" for accuracy on day one, a testable target, and a credible TM Forum submission.

The senior move wasn't building the model — it was building the trustworthy system around a validated one.

Operationalising

ServiceNow integration + workflow automation + adoption

DD → SERVICENOW

Monitor → webhook → incident. Severity→priority. Service→CMDB. u_datadog_monitor_id. Deduplication.

SERVICENOW → DD

Resolve ticket → Business Rule → close DD alert. Work notes sync. No orphans.

SECURITY TICKETS

SAST/SCA findings → SNOW issues. Fix → re-scan → auto-close. Same integration for ops + security. 50% less surface.

Auto-Remediation

Pre-approved playbooks

Restart, scale, clear cache, rotate creds. Approved upfront, executed at alert time. Every action audited + reversible. Workflows encode institutional knowledge.

Intelligent Alerting

ML-powered monitors

Anomaly detection (baseline deviation). Forecast monitors (predict exhaustion). Composite alerts (multi-condition). No alert fatigue.
